# weblist review profile

## What this is

A single-binary Go web file browser. It serves a directory over HTTP with listings, downloads, file
previews (markdown, CSV, syntax-highlighted code), an optional JSON API, optional multi-file ZIP
download, optional upload, and an optional read-only SFTP listener on its own port. It is distributed
as a binary and a Docker image and run by third parties on their own machines. The frontend is HTMX
with server-rendered templates and a small amount of hand-written JavaScript; there is no build step
and no framework.

## What a real failure looks like here

- a file outside the configured root becomes readable, or an exclude pattern stops being honored
- a path that should require the password is served without it, or a write path accepts an anonymous request
- an upload escapes the root, overwrites something it should not, or bypasses the exclude rules
- a listing, download or preview breaks for an ordinary file, or the page breaks after an HTMX swap
- the server hangs, panics or leaks a handle on a request an anonymous client can send

## Blast radius

Every third-party deployment of a released binary, most of them exposed to a network by definition.
Nothing is written except uploads into the served root, and there is no database, no user store and no
external service, so damage is bounded by what is reachable under the root. Security defaults matter
more than in a tool that only ever runs behind a login, because the common deployment is a public
listing.

## Who runs it

Solo maintainer, no on-call, no staging. Issues and pull requests come from outside users. Releases are
tagged by hand. CI runs tests, race and golangci-lint on every push, so anything the linter catches is
already caught.

## Reporting bar

Report a defect that changes what a user sees or what an attacker can reach. A finding needs a concrete
trigger and an observable consequence, not a category.

Do not report:

- style, naming or formatting golangci-lint already enforces, its config is in `.golangci.yml`
- a suggestion to add an abstraction, an interface or a layer that has one caller
- a hardening measure with no reachable path in this codebase
- missing handling for input the router or the flag parser cannot produce
- test structure preferences when the behavior is covered

## Deliberate conventions, not defects

- comments are lowercase in function bodies; godoc starts with the element name
- errors are wrapped with `fmt.Errorf("context: %w", err)`, logging goes through `lgr`
- identifiers are private unless used outside the package
- mocks are generated by `moq` into a `mocks` package and are never edited by hand
- dependencies are vendored and the vendor directory is committed
- one test file per source file, table-driven with testify
- HTMX over JavaScript; a JS solution where a server-rendered one works is the thing to question
- optional behavior arrives as a flag that is off by default, so existing deployments do not change
- the full-page and HTMX-partial renders build their template data separately; that duplication is
  known, and a finding about it should be about the two drifting, not about the shape
